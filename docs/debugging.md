# Отчёт об отладке

Документ фиксирует ошибки, возникшие при развёртывании стенда и при сборке
сайта, и способы их устранения. Таблицы разделены по стадиям: сначала стенд,
затем сайт, затем публикация.

Ошибки стенда собраны из журнала разработки проекта, ошибки сайта и публикации
воспроизведены и проверены на macOS (darwin/arm64), Python 3.14, MkDocs 1.6.1,
mkdocs-material 9.7.7.

## 1. Стенд: Node.js, Yarn, сборка

| Симптом | Причина | Устранение |
|---|---|---|
| `Error: This package doesn't seem to be present in your lockfile` | Не выполнена установка зависимостей либо удалён `yarn.lock` | `yarn install` |
| `Cannot find module ...` при запуске | Не построен PnP-резолвинг | `yarn install`. Файлы `.pnp.cjs` и `.pnp.loader.mjs` вручную не удалять — установка пересоздаёт их сама |
| `Problem loading http3-quiche transport` | Не собран нативный модуль QUIC | `yarn install`, либо точечно `yarn rebuild @fails-components/webtransport-transport-http3-quiche` |
| `Top-level await is currently not supported with the "cjs" output format` | В `package.json` потеряно `"type": "module"`, из-за чего `tsx` считает `.ts` CommonJS | Вернуть `"type": "module"` |
| `yarn tsc` не находит файлы | В `tsconfig.json` в `include` указан несуществующий каталог | Должно быть `"include": ["src/**/*.ts"]` |

## 2. Стенд: сеть, сертификат, браузер

| Симптом | Причина | Устранение |
|---|---|---|
| `EADDRINUSE: udp 4433` | Занят QUIC-порт | Сменить порт: `WT_PORT=4434 yarn start` |
| HTTP работает, WebTransport не подключается | UDP-порт закрыт брандмауэром либо занят | Проверить `WT_PORT`, открыть порт |
| `Chrome: invalid certificate` | Самоподписанный сертификат просрочен или сменён | Удалить каталог `certs/`, затем `yarn cert` |
| `Failed to launch the browser process` в `yarn e2e` | Chrome не найден по стандартному пути macOS | `CHROME_PATH=/путь/к/chrome yarn e2e` |
| В шапке стенда список недоступных API | Открыто не в Chromium либо камера заблокирована вне HTTPS/localhost | Открыть в Chrome/Edge |
| Метрики подозрительно быстрые, RTT < 1 мс | Это норма для loopback, а не ошибка | Не считать характеристикой транспорта, см. [Ограничения](limitations.md) |

## 3. Сайт: Python-окружение

| Симптом | Причина | Устранение |
|---|---|---|
| `zsh: command not found: pip` | В Homebrew-установленном Python бинарник называется `pip3`; `pip` в `PATH` отсутствует | Использовать `pip3` либо `python3 -m pip` — на macOS это разные команды |
| `zsh: command not found: virtualenv` | Пакет `virtualenv` не установлен | Либо `pip3 install virtualenv`, либо использовать встроенный `python3 -m venv .venv-docs`: для проекта, не требующего установки пакетов внутрь окружения, достаточно модуля из стандартной библиотеки |

Проект использует `python3 -m venv`: состав зависимостей полностью
фиксируется `requirements.txt`, отдельная установка `virtualenv` не требуется.

## 4. Сайт: сборка

### `base_url` роняет строгую сборку

```text
WARNING -  Config value 'base_url': Unrecognised configuration name: base_url
Aborted with 1 configuration warnings in 'strict' mode!
```

В MkDocs 1.6 **нет** опции верхнего уровня `base_url` — существует только
`base_url` у отдельных плагинов. Базовый путь выводится из `site_url`, поэтому
отдельное поле задавать нельзя.

Устранение: задать полный адрес с висящей косой чертой и больше ничего:

```yaml
site_url: "https://heavygendalf.github.io/rtc-benchmark/"
```

### `sitemap.xml` собирается пустым

При незаданном `site_url` файл создаётся, но содержит ноль URL — это
проверяемый признак неверной настройки базового адреса, а не пустая сборка.

Устранение: прописать `site_url` и пересобрать — в `sitemap.xml` появляются все
страницы с префиксом `/rtc-benchmark/`. Заодно начинают формироваться
канонические ссылки `<link rel="canonical">`.

### Шрифты сайта зависят от внешнего CDN

Тема Material подключает Google Fonts с `fonts.googleapis.com`. Для публикации
на закрытом хостинге и для работы без внешней сети это неприемлемо.

Устранение в `mkdocs.yml`:

```yaml
theme:
  font: false
```

!!! warning "Проверено: подходит только целочисленное `font: false`"
    Варианты `font.text: false` и `font.code: false` подключение Google Fonts
    **не убирают** — `<link>` на `fonts.googleapis.com` остаётся в HTML.
    Проверено экспериментально: при `font: false` вхождений `fonts.googleapis`
    в собранном HTML — 0, при `font.text: false` и при `font.code: false` — по
    одному. После отключения применяется системный шрифт.

### Ссылку нельзя поставить в `copyright`

Значение `copyright` подставляется в шаблон как есть: **markdown не
обрабатывается**, а относительные пути не переписываются под адрес страницы.
Строка `[CC BY 4.0](license.md)` выводится текстом, и ссылка оказывается
битой — при проверке целевой файл не находится ни на главной странице, ни на
подстранице.

Сырой HTML в `copyright` выводится корректно, но относительный `href` всё
равно не переписывается. Устранение: в `copyright` оставить только текст, а
разбор лицензий вынести на отдельную страницу, добавленную в `nav`.

### `--strict` превращает предупреждения в ошибку

Строгая сборка падает на ссылку на несуществующую страницу и на файл в `docs/`,
не попавший в `nav`. Так и должно работать: молча потерянная страница хуже
явной ошибки. Устранение: добавить страницу в `nav` либо исправить ссылку.

## 5. Публикация

| Симптом | Причина | Устранение |
|---|---|---|
| На GitHub попал стенд без сайта | `docs/`, `mkdocs.yml`, `requirements.txt` не были закоммичены | Закоммитить их **до** настройки Actions, иначе первый деплой соберёт пустой сайт |
| Сайт открывается на Pages, но ломается в подкаталоге другого хостинга | В `site_url` указан домен с чужим подкаталогом либо в тему добавлены абсолютные пути | Собирать с относительными путями. При `use_directory_urls: true` ссылки вида `../about/` строятся относительными и подходят любому хостингу |
| Деплой падает с `Error: Get "https://api.github.com/...": Not Found` | У `GITHUB_TOKEN` нет прав на Pages | Выдать job `deploy` права `pages: write` и `id-token: write` в блоке `jobs.deploy.permissions`. На уровне workflow эти права не нужны и выдавать их не следует: job `build` исполняет код из pull request |
| Сайт не появляется по адресу репозитория | В настройках репозитория `Settings → Pages → Source` выбрано не `GitHub Actions` | Переключить Source на `GitHub Actions` — обязательный шаг для связки `upload-pages-artifact` + `deploy-pages` |
| Публикация не запускается сама | Workflow добавлен после последнего пуша и ни разу не запускался | `Actions → Deploy site to GitHub Pages → Run workflow` |
| Job «Публикация» серый (skipped) при ручном запуске | Выбрана не ветка `main` либо упала сборка (`needs: build`) | Условие `if` у `deploy` пропускает любой ref, кроме `refs/heads/main`. Выбрать в поле запуска ветку `main` и убедиться, что «Сборка сайта» зелёная |
| Job «Публикация» серый (skipped) на pull request | Так и задумано | Публикуется только `main`. Серый job — норма для pull request, а не сбой; смотрите на зелёную «Сборка сайта» |

### Два подхода к публикации

| | `peaceiris/actions-gh-pages` | `actions/upload-pages-artifact` + `actions/deploy-pages` |
|---|---|---|
| Куда попадает | Ветка `gh-pages` в том же репозитории | Сборка `site/` в окружение Pages |
| Публикация | `git push` в `gh-pages` | Официальный API Pages, без правки ветки |
| Требует | Права `contents: write` | `pages: write`, `id-token: write` |
| Источник в UI | Вкладка `gh-pages` | Вкладка `Actions` |

Выбран официальный вариант `upload-pages-artifact` + `deploy-pages`: он не
плодит вторую ветку с копией сайта и показывает результат сборки прямо в
журнале Actions. Вариант `peaceiris` проще в отладке, так как появившаяся ветка
`gh-pages` доступна для просмотра обычным git.

## 6. Что проверено, а что ещё нет

**Проверено локально:**

- `mkdocs build --strict` проходит без предупреждений;
- `sitemap.xml` содержит адреса всех страниц с префиксом `/rtc-benchmark/`;
- канонические ссылки формируются с полным адресом;
- ссылки в HTML относительные, поэтому сайт переносится в подкаталог;
- внешние CDN не используются: `fonts.googleapis.com` и `fonts.gstatic.com` из
  сборки убраны, применяется системный шрифт;
- поиск собирается локально: `search_index.json` и worker-скрипт отдаются с
  собственного домена, обращений к внешним индексаторам нет;
- вёрстка не ломается без внешних шрифтов.

**Не проверено:**

- интерактивная работа поиска в браузере — индекс корректен, но ввод в поле
  поиска автоматизированно не проверялся;
- HTTP-коды и поведение сайта на реальном домене GitHub Pages;
- сборка в CI на Ubuntu — workflow написан, но ещё ни разу не выполнялся;
- формулы: математических выражений в контенте нет, MathJax не подключён. При
  их добавлении MathJax по умолчанию загружается с внешнего CDN, который на
  закрытом хостинге будет недоступен — тогда потребуется локальный MathJax.
- строка `Fonts: SIL OFL 1.1` в собранном HTML относится к комментарию внутри
  инлайновых SVG-иконок Font Awesome, а не к загрузке шрифтов. Сетевых запросов
  она не создаёт, устранять ничего не нужно.
