# T1. Сравнение генераторов статических сайтов

Дата замера: 30 сентября 2026. MacBook Pro, macOS, локальный диск.

Ни одна сборка не ходит в сеть за MathJax. Sphinx и Quarto лишь вписывают в
HTML адрес скрипта на CDN — сам файл скачивает уже браузтор при открытии
страницы:

```
sphinx/_build/html/page-01.html  <script src="https://cdn.jsdelivr.net/npm/mathjax@4/tex-mml-chtml.js">
quarto/_site/page-01.html         <script src="https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-chtml-full.js">
mkdocs/site/page-01/index.html    <script src="assets/mathjax/tex-svg.js">
```

Поэтому замер времени сборки не зависит от сети, а проверка формул в браузере
зависит: без сети Sphinx и Quarto показали бы неотрисованные формулы. Проверка
выполнялась отдельно, в разделе «Формулы».

## Метод

Один и тот же проект — 15 страниц с русскими заголовками, таблицей и
формулой — генерируется каждым инструментом своим скриптом
(`make_ssg_project.py`), поэтому содержание страниц не влияет на сравнение.
Front matter добавляется только Pelican: он берёт заголовок из метаданных, а
не из первой строки Markdown. Текст страницы при этом одинаковый.

Для каждого генератора: 5 сборок подряд, первая отбрасывается как прогрев
кэша импортов и файлов, в таблицу идут 4. Перед каждым запуском выходной
каталог удаляется целиком, иначе часть файлов переживает сборку и время
занижается.

Четыре замера на генератор — мало для статистики: таблица показывает порядок
величин, а не точное число.

Скрипты — в `t1-scripts/`, сырые запуски — в `t1-measure-ssg.log`.

### Откуда в каждом случае разное число html-файлов

Во всех четырёх случаях контентных страниц 15, остальное — служебное:

| Генератор | html | Из них |
| --- | --- | --- |
| MkDocs | 16 | 15 страниц + сгенерированный `404.html` |
| Sphinx | 18 | 15 страниц + `index.html` корень сайта + `genindex.html` + `search.html` |
| Pelican | 22 | 15 страниц + 7 служебных: `archives.html`, `authors.html`, `author/t1.html`, `categories.html`, `category/misc.html`, `tags.html`, `bystryi-start.html` |
| Quarto | 16 | 15 страниц + `index.html` на 231 байт, который не страница, а редирект |

Две особенности, о которых стоит знать:

- **Pelican** строит имя файла из заголовка и транслитерирует кириллицу, поэтому
  `«Команды»` становится `komandy.html`, а не `page-04.html`. Плюс он по
  умолчанию добавляет страницы архива, авторов, категорий и тегов — это и есть
  остальные 7 файлов.
- **Quarto** получает 16-й файл из-за отсутствия `index.qmd` в сгенерированном
  проекте: корень сайта закрывается страницей-заглушкой с редиректом на
  `page-03.html`. На время сборки это 231 байт и не влияет.

## Формулы

Проверка в браузере (`t1-formulas.log`): ждём появления отрисованной формулы,
а не фиксированную пауску.

| Генератор | Результат | Чем рисует |
| --- | --- | --- |
| MkDocs | отрисована | локальный MathJax, SVG |
| Sphinx | отрисована | MathJax 4 с CDN, CHTML |
| Pelican | осталась текстом | поддержки нет |
| Quarto | отрисована | MathJax 3 с CDN, CHTML |

Версии здесь не догадка: они названы прямо в адресе скрипта, который
генератор вписал в HTML (`mathjax@4` у Sphinx, `mathjax@3` у Quarto). Внутри
сборки MathJax нет — ни у Sphinx, ни у Quarto, — поэтому и размеры такие
разные.

Признак отрисованной формулы — контейнер `mjx-container`, а не `svg` внутри
него: в режиме CHTML (так настроены Sphinx и Quarto) MathJax строит HTML, и
svg там нет вовсе. Первая версия проверки искала только svg и объявляла
CHTML-формулы неотрисованными — это ложный отрицательный результат.

## Что стоит знать про настройку

Три находки, каждая стоила отдельного захода. Все три дают тихую неправильную
документацию — сборка проходит, ошибок нет.

1. **MyST не понимает `toctree` без явного указания.** Ни `.. toctree::`, ни
   `:::{toctree}` не разрешились: директива попала в HTML как обычный текст,
   сборка завершилась с 15 предупреждениями `document isn't included in any
   toctree`, оглавление на главной не работало. Сработала огороженная форма
   ` ```{toctree} `. Исходники не попадали в оглавление — это ровно тот
   случай, когда нужен `-W`, а не `-q`.

2. **`$$...$$` в MyST не включён по умолчанию.** Без
   `myst_enable_extensions = ["dollarmath"]` формула превращается в обычный
   текст, и Sphinx не говорит ни слова.

3. **Математика в MkDocs требует подключения отрисовщика.** Настройки
   `pymdownx.arithmatex` достаточно, чтобы появилась разметка, но без
   `extra_javascript` в собранном сайте нечем рисовать формулу.

## Вывод

Скорость сборки в этом проекте не была ограничением: любой из четырёх
генераторов укладывается в секунды. Ограничение — поддержка формул, и здесь
конфигурации неравноценны:

- **MkDocs** — единственный, у которого формулы рисуются локально, без
  зависимости от внешней сети. Для документации, которую читают в закрытом
  контуре, это решающий довод.
- **Sphinx и Quarto** рисуют формулы, но тянут MathJax из CDN: вне сети
  документация выглядит рабочей, а формулы в ней не работают.
- **Pelican** формулы не поддерживает вовсе и без плагинов.

Выбран MkDocs — он уже используется в проекте, и локальный MathJax в нём
работает. Quarto отпадает по времени и по зависимости от CDN, Pelican — по
формулам, Sphinx уступает тем же требованиям при более сложной настройке.
